RUTE & PEMBAGIAN HALAMAN — JANGAN CAMPUR
`/login` -> `/dashboard` -> `/transaksi-baru` -> `/checkout` -> `/transaksi-berhasil`.
Modul terpisah:
- `/pemesanan` = daftar PO, status Dipesan / Diproses / Sudah Datang / Selesai; kasir bisa buat PO dan memantau. Klik PO ke detail.
- `/pemesanan/baru` = FORM BUAT PO: pilih/tambah pelanggan, pilih frame/lensa, pilih resep tersimpan untuk lensa, simpan snapshot parameter resep per PO, simpan status awal Dipesan. TOMBOL `Simpan PO`, BUKAN `Proses Pembayaran`.
- `/pemesanan/:id` = detail PO, timeline dan data terkait. Kasir tidak boleh mengubah status proses Admin (Diproses / Sudah Datang).
- `/riwayat-transaksi` = riwayat transaksi terfilter, search, view nota.
- `/pembayaran` = daftar/status pembayaran & akses bukti, BUKAN halaman tambah produk atau stok.
- `/pelanggan` = MASTER pelanggan: list, search berdasarkan nama/no HP, add/edit, detail pelanggan & riwayat resep; jangan menggabungkan semua form checkout ke sini.
- `/resep-mata` = arsip resep pelanggan; add/edit sesuai izin, ukuran kanan/kiri dan tanggal resep; pemeriksaan mata dilakukan DI LUAR aplikasi.
- `/checkout` = pelanggan, pilih resep (jika relevan), produk terpilih, total, metode pembayaran; jangan tampilkan katalog frame besar lagi.
- `/transaksi-berhasil` = nomor transaksi, total, produk, metode, status lunas, cetak struk, transaksi baru, lihat riwayat.
Untuk data yang belum ada di referensi visual spesifik (misalnya `/pemesanan/baru` dan `/resep-mata`), buat layout baru DENGAN COMPONENTS YANG SAMA, bukan mengulangi screenshot halaman Transaksi Baru.

ALUR DAN PERILAKU KASIR SESUAI PRD
- Role access: hanya Kasir. Transaksi dan data sesuai cabang yang dipilih/ditugaskan. Jika hanya demo lokal, jangan klaim RBAC aman sisi server.
- Produk frame dan lensa dipisah kategori; Kasir BOLEH MELIHAT dan memilih produk, tetapi TIDAK CRUD produk, edit harga, set stok minimum, distribusi barang, atau akses data cabang lain.
- Pelanggan: nama dan nomor HP minimal, validasi, pencarian. Resep: tanggal, mata kanan OD dan kiri OS, simpan/lihat sejarah, pilih resep ketika buat pesanan lensa.
- Pembelian langsung: pilih barang -> keranjang -> checkout -> pilih pelanggan -> pilih resep (bila perlu) -> bayar via tunai atau simulasi metode digital -> sukses -> struk. Kurangi stok DEMO tepat satu kali pada transaksi sukses, jangan saat menambahkan ke keranjang atau payment pending. Jangan stok minus.
- PO dibuat Kasir jika barang perlu dipesan; status awal Dipesan. Admin Cabang yang memproses Diproses dan Sudah Datang. Kasir melihat status, menghubungi pelanggan dan menangani pembayaran/penyelesaian sesuai aturan final PRD; jika otoritas transisi ke Selesai belum dipastikan, jangan diam-diam memberikan akses edit status.
- Metode pembayaran tunai, transfer, QRIS, e-wallet berdasarkan PRD; gateway nyata tidak perlu untuk mockup frontend, beri label simulasi pada metode digital, tampilkan state loading, success/failure dengan benar dan hindari transaksi ganda.
- Semua tabel/form punya empty, error, loading, disabled, success states yang proporsional, tanpa mengubah desain.
- Tidak boleh ada dekorasi emoji di dalam UI (kecuali kalau benar-benar dituntut gambar referensi; lebih baik icon SVG). Foto eyewear tetap konsisten.
